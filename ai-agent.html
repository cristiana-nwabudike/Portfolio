Multi-Purpose AI Admin Agent

A Claude-powered agent connected to Salesforce, Slack, and Gmail — built to accelerate the parts of admin work that don't need a human.

AI-Assisted Admin Workflows

The overview.

Salesforce admin work has a long tail of recurring tasks — meeting prep, status updates, stakeholder comms, license audit prep, release notes drafting. Each one is small, but together they eat real focus time. I designed a multi-purpose AI agent to take the repetitive parts off my plate while keeping me firmly in the driver's seat for any external action.

The challenge.

  • Recurring admin tasks (daily briefs, meeting prep, sprint release notes) consuming focus time that should go toward higher-leverage work.
  • Stakeholder communication needing the right tone and context for very different audiences (technical engineers vs. business leadership vs. security partners).
  • Untrusted content (emails, Slack messages, Salesforce records) flowing into the agent's context, creating prompt injection risk.
  • Wanting AI assistance without giving up explicit human approval over anything externally-visible.

The solution.

Detailed context document & system prompt

Authored a structured context document covering my role, stakeholders, Salesforce environment, signal hierarchy, and current quarter priorities — so the agent answers like someone who's been in the role, not a generic assistant.

MCP-based integrations

Connected the agent to Salesforce, Slack, Gmail, and Atlassian through the Model Context Protocol — giving it the reach to actually pull live context (open issues, recent threads, calendar) instead of guessing.

Explicit approval rails

Configured the agent to default to drafts (Slack drafts, Gmail drafts) for anything externally-visible — nothing gets sent without me reviewing it first. Internal-only operations (reading data, summarizing, querying) run freely.

Prompt injection defense

Built guardrails that treat content arriving from emails, Slack, and Salesforce records as untrusted data — the agent will not act on embedded instructions from those sources without my explicit confirmation.

Named workflows

Defined repeatable patterns the agent recognizes by name — 'daily brief,' 'meeting prep,' 'release notes draft' — so I can trigger structured output with a single phrase.
