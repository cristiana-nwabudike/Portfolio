QR-Based Church Check-In System

Apex, LWC, and a public Experience Cloud Site — built to make Sunday morning faster.

Volunteer Admin (Self-Built Solution)
Platform
Salesforce + Apex + LWC + Experience Cloud Site

Nonprofit Operations (Pro Bono)

The overview.

Sunday morning check-in for a multi-hundred-member church can't be a bottleneck. The team needed something faster than paper or a tablet form — something members could trigger themselves from their phone, with no app to install. As an admin who's also growing development skills, I took on the Apex and LWC pieces myself, learning on the way and shipping to production.

The challenge.

  • Need a check-in experience that works for unauthenticated members on their own phone — no login, no app install.
  • Each Contact needs a unique, opaque token (not the Contact ID) to prevent URL enumeration.
  • Same QR code URL every week — service context (campus, date, service type) must change without re-issuing tokens.
  • Guest user security model needs to be tight: insert-only access to Attendance, no enumeration possible.

The solution.

Unique token model with external ID

Added a CheckIn_Token__c field on Contact (Text, Unique, External ID, Required) populated via batch Apex on initial load and a record-triggered Flow on new Contact creation.

Apex controller with secure SOQL

Wrote an Apex controller using WITH SECURITY_ENFORCED for the Contact lookup, running without sharing only for the guest context and scoping queries tightly. Idempotent check-in logic prevents double-counting.

Lightning Web Component for the check-in page

Built a public-facing LWC hosted on a Salesforce Experience Cloud Site, reading the token from the URL parameter and surfacing a friendly success or error state.

Custom Metadata for service context

Created an Active_Service__mdt Custom Metadata Type (Campus, Service Type, Service Date, Is Active) — the QR code URL stays constant while the active service record changes weekly. Attendance records get stamped automatically.

Test coverage & hardened guest profile

Wrote Apex test methods covering happy path, invalid token, inactive service, and rate-limit branches. Guest user profile stripped to insert-only on Attendance with no enumeration access.
